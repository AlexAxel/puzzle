# Puzzle Atelier — типы разреза и подготовка фигурных форм

**Состояние:** 31 октября 2026. **Базовая стабильная версия:** ветка
[`snapshots/classic-stable-2026-10-31`](https://github.com/AlexAxel/puzzle/tree/snapshots/classic-stable-2026-10-31),
коммит `477107c4`. Новые идеи не должны ломать эту контрольную точку.

## Что уже реализовано

- **Классический**: прежняя геометрия, прежние настройки, перемещение и соединение групп. Алгоритм классических стыков не изменён.
- **Узорный (экспериментальный v1)**: процедурные лепестковые / завитковые края с двумя или тремя фигурными выступами и впадинами вдоль каждой внутренней границы; некоторые соединения четырёх деталей слегка смещены. **Это не режим с готовыми зверями и птицами**. Он лишь пробует более плотную, декоративную геометрию без внешних ассетов.
- Все внутренние границы создаются **ровно один раз** и обходятся двумя соседними деталями в разных направлениях. Базовый пазл продолжает обрабатываться в текущем Canvas-движке.
- Новый модуль `ornate-cut.js` не зависит от рендеринга, так что геометрию можно вынести в самостоятельный пакет/экспортёр.

## Что присылать для фигурных пазлов (whimsy pieces)

**Предпочтительный формат: SVG с векторным контуром.** Для каждого объекта — отдельный исходник:
`bird.svg`, `fox.svg`, `butterfly.svg`, `leaf.svg` и т.д.

### Требования к исходнику

1. Один замкнутый внешний силуэт с корректным `viewBox`; лучше `<path d="... Z" fill="black"/>`. Можно использовать несколько замкнутых контуров, если их объединить в одну геометрическую фигуру до экспорта.
2. Отсутствие фонового прямоугольника, надписей, текстур, растров, клип-масок, фильтров, художественных обводок, случайных групп и встроенных зависимостей.
3. Контур должен быть простым: без самопересечений, тончайших волосков, чрезвычайно узких перешейков и почти соприкасающихся петель.
4. Силуэт должен **узнаваться целиком**; у птицы может быть заметный клюв, хвост и крыло, но без десятков мелких выступов.
5. Рекомендуемый рабочий `viewBox="0 0 1000 1000"`. Абсолютные пиксели не так важны, как чистота масштабируемого контура и пропорции.
6. Стартовая реализация **без внутренних отверстий**, поскольку они создают отдельные топологические островки. В будущем отверстия возможны как дополнительная задача (дырки/вставки).
7. Каждая фигура должна быть либо создана вами, либо приобретена/получена с **подтверждёнными правами на коммерческую адаптацию**. Нужны источник, автор и информация о лицензии.

### Минимальный пример формата

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1000 1000">
  <!-- Данные d здесь — ваши собственные замкнутые кривые, а не картинка из PNG. -->
  <path id="bird" fill="#000" d="M 150 550 C 270 400 440 380 600 500
    C 720 490 800 530 860 620 C 670 780 320 780 150 550 Z"/>
</svg>
```

Это пример формата файла, **не** готовый силуэт птицы.

Если исходно есть PNG с прозрачным фоном, он подходит **как референс**,
но для реальной нарезки желательно вручную обвести силуэт в Inkscape/Illustrator
и очистить результат. Автоматическая векторизация без редактирования часто даёт шумные узлы.

### Дальнейшие метаданные фигуры

Храним дополнительно к SVG поля: `id`, `category` (`animal`/`bird`/`plant`/`symbol`),
`recommendedScale`, `minNeckWidth`, `rotationsAllowed`, `tags`,
`source`, `license`, `author`. Полезны и тематические наборы
(лес, море, космос, средневековье, зима).

## Почему нельзя просто наложить SVG-маску поверх сетки

Силуэт зверя занимает целую площадь и пересекает несколько обычных ячеек. Если просто наложить
маску поверх уже созданных деталей, возникнут перекрытия, пустоты, островки и разрывы стыков.

Для реального фигурного пазла нужен **общий планарный граф разреза**:

1. Создаём внешнюю границу изображения.
2. Расставляем выбранные фигуры как непересекающиеся замкнутые полигоны с полями безопасности
   от края изображения и друг от друга.
3. Фиксируем их как цельные детали/области с определёнными контурами.
4. Оставшуюся площадь делим на узорчатые промежуточные детали,
   используя ограниченную сетку, Voronoi или собственный алгоритм разбиения.
5. Строим набор **уникальных общих рёбер**, которые каждая соседняя деталь использует со своей стороны.
6. Проверяем замкнутость, отсутствие перекрытий и пустот, минимальную толщину перешейков,
   площадь деталей, граф смежности и отсутствие крошечных осколков.
7. Только после валидации отрисовываем маску каждого фрагмента и игровую текстуру.

## Перенос в Unity

Рекомендуется **отделить геометрию пазла от его визуализации и действий игрока**.
Единый результат генератора — сериализованный набор контуров, позиций и смежности.
Web Canvas и Unity `Sprite/PolygonCollider2D`/меши используют эти данные независимо.

Условный формат:

```json
{
  "version": 1,
  "seed": 12345,
  "style": "whimsy",
  "imageSize": [1600, 900],
  "pieces": [
    {
      "id": 0,
      "outline": [[0, 0], [120, 0], [116, 98]],
      "neighbors": [1, 4],
      "origin": [64, 51],
      "kind": "bird",
      "sourceShapeId": "bird-01"
    }
  ]
}
```

Это **схематический контракт**, не готовый файл для текущего движка.
Для реальной поставки нужны все вершины и возможные отверстия, UV-координаты,
проверка ориентации полигонов, общий масштаб, смежные рёбра, идентификатор версии генератора
и сохранённый random seed.

Для геометрических булевых операций при развитии проекта рассмотреть:

- **Paper.js** (MIT) для прототипирования в браузере.
- **martinez** (MIT) для объединения/пересечения/разности полигонов в JS.
- **Clipper2** (Boost Software License 1.0) — особенно интересно для Unity: есть исходная реализация на C#.

Нужно учитывать сторонние зависимости и тексты лицензий при включении соответствующих
библиотек; сейчас **их код в репозиторий не копировался**.

## Open-source решения для изучения

- [weevilgenius/puzzle-generator](https://github.com/weevilgenius/puzzle-generator) — MIT.
  Расширяемые стадии seed points → pieces → tabs, SVG-экспорт. Хороший архитектурный ориентир.
- [pburney/Puzz](https://github.com/pburney/Puzz) — MIT.
  Импорт произвольных наборов `SVG -> JSON`; полезно для работы с заранее спроектированными фигурными раскладками.
- [AngusJohnson/Clipper2](https://github.com/AngusJohnson/Clipper2) — Boost-1.0.
  Булевы операции над полигонами; C# пригоден для Unity.
- [w8r/martinez](https://github.com/w8r/martinez) — MIT.
  Полигональная геометрия на JS/TypeScript.
- [Shadow-Puppet/JigsawGenerator](https://github.com/Shadow-Puppet/JigsawGenerator) —
  интересная архитектура Rust/WASM с едиными рёбрами, но лицензия пока указана как `TBD`;
  **не копировать код** в коммерческую игру без разрешения.
- [mchrisman/jigsawGenerator](https://mchrisman.github.io/jigsawGenerator/) —
  есть готовые «whimsy» и «deco» выкройки с пометкой «free for use»,
  но перед включением файлов в коммерческий продукт требуется прояснить правовой статус каждого ассета.

## Предлагаемый следующий эксперимент

Вместо разработки десятков отдельных фигур сначала сделать **компактный набор из 12–20 SVG**:
птица, бабочка, лисёнок, рыба, лист, дерево, луна, звезда, ключ, корона, кот, сова.
Подобрать один образец 48–80 деталей. Цель первого эксперимента: 6–10 узнаваемых фигур,
остальные — промежуточные органические контуры без дыр и перекрытий.
После проверки UX масштабировать каталог.

### Связанные игровые идеи

- «Найди редкие фигуры» — игрок собирает небольшую коллекцию особо красивых фигурных деталей.
- Тематические наборы: сюжетные узоры для историй, сезонов, животных, путешествий.
- Реставрация выбранной фигурной детали перед установкой; отдельный микроцикл ASMR без
  обязательной очистки каждой детали.
- Режим без подсказки исходной картинки и режим с контуром: разные уровни сложности
  без необходимости менять изображение.
